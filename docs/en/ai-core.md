# AI Core Setup

Guide for running the AI Core pipeline and exporting YOLO models from `.pt` to `.engine` (TensorRT) format to accelerate inference on the Jetson Orin Nano.

| Section | Description |
|---------|-------------|
| [Run AI Core test](#run-ai-core-test) | Run the face recognition pipeline from camera |
| [Export model `.pt` → `.engine`](#export-model-pt--engine) | Convert YOLO `.pt` to TensorRT `.engine` (FP16/INT8) |

## Run AI Core test

Pipeline for person detection (YOLO) + tracking (ByteTrack) + face recognition (InsightFace).

### Preparation

```bash
cd src/ai_core

# Install dependencies
pip install -r requirements.txt
```

### Configure known faces source (SQLite database)

AI Core retrieves pre-computed face embeddings from the SQLite database of `logic_service`.

Configure in the `.env` file of `src/ai_core/`:

```env
# Get known faces from SQLite database instead of folder
FACE_DB_SOURCE=sqlite

# Path to the SQLite file containing the face embeddings table
FACE_DB_PATH=logic_service/logic_service.db
```

> Embeddings in the DB are generated by `logic_service` when users are registered (via admin/app). AI Core only reads from, and never writes to, the DB.

### Test command

```bash
# Run with CUDA (Jetson)
python main.py --device cuda
```

Keyboard controls:
- `q` — Quit

See the remaining options in [src/ai_core/README.md](../../src/ai_core/README.md).

## Export model `.pt` → `.engine`

A TensorRT engine is only compatible with **the exact GPU architecture it was built on**, so the export command **must be run directly on the Jetson Orin Nano** (the target device). An engine built on another machine (PC, server, different Jetson generation) **will not run**.

Script: [src/ai_core/export_tensorrt.py](../../src/ai_core/export_tensorrt.py)

### Export commands

```bash
cd src/ai_core

# Export all default models in the pipeline (FP16)
python export_tensorrt.py

# Export a specific model
python export_tensorrt.py --models yolo11l.pt

# Export with a custom image size
python export_tensorrt.py --models yolo11l.pt --imgsz 640

# Export with INT8 quantization (requires a dataset for calibration)
python export_tensorrt.py --models yolo11l.pt --int8 --data coco128.yaml
```

### Parameters

| Parameter | Default | Description |
|-----------|---------|-------------|
| `--models` | `yolo11l.pt`, `yolo11l-pose.pt`, `yolov8n-face-mask.pt`, `yolov8m-protective-equipment-detection.pt` | List of `.pt` files to export |
| `--imgsz` | `640` | Inference image size (square) |
| `--int8` | `False` | Enable INT8 quantization (requires `--data` for calibration) |
| `--data` | `None` | YAML dataset file used for INT8 calibration (e.g. `coco128.yaml`) |
| `--workspace` | `4` | TensorRT workspace (GB) |

### After export

The `.engine` file is created in the same directory as its corresponding `.pt` file. Update the config / `.env` so the pipeline uses the engine instead of the `.pt`:

```bash
YOLO_MODEL=yolo11l.engine
MASK_MODEL_PATH=yolov8n-face-mask.engine
PPE_MODEL_PATH=yolov8m-protective-equipment-detection.engine
```

> Note: if the `.engine` file already exists, the script will skip it to avoid rebuilding. Delete the old file if you want to rebuild from scratch.
